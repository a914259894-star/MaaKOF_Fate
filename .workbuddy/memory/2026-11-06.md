## v1.2.30 竞技场页面路由重构（单入口 + 依次判页）

**用户诉求**：1v1 用 v1.2.27 时「误点其他界面好多次」。要求改成：
「从一个入口进入 → 所有页面依次判别（战斗最优先、未知界面等待）→ 判出是哪个页面
再进那个页面的流程 → 走完一次流程回到入口 → 再判一次」。

**根因**：旧 arena.json 是「每个节点各写一串 next」，同一批候选复制十几份，而且
next 里混着**点击**节点：
- `Arena_Enter_1v1` 只看 `main_arena_btn`、阈值 0.7 就点
- `Arena_Enter_Master` 三个模板全是 0.7
- `Arena_MasterMatch` 是完全盲点 (1135,634)
只要某个宽泛模板在错误页面误命中，就在那一页点一下。

**改法**：
- 新增 `assets/agent/page_router.py`
  - `ArenaRouter`：截一张图，本地 cv2 按优先级判页
    `战斗 > KOF段位提升 > 胜负结算 > 选人 > 大师团 > 竞技场主页 > 主城 > 未知`
    → `context.override_next(argv.node_name, [目标])` 精确路由
    → 同时 `override_pipeline({目标: {"next": [自己]}})` 把回路改回当前 Router
      （1v1/大师是两个 Router 节点，不改回路会串模式）
  - 竞技场主页点 1V1/大师、主城点 KO竞技，都在 Router 内做，且**先模板命中才点**
  - 未知页只等待，连续 25s 才交 `ArenaSafeBack`
  - `ArenaSettleOk` / `ArenaRankUp` / `ArenaMasterMatch`：DirectHit + 自定义动作，
    动作内部先复核页面再点（原来 SettleOk/RankUp 是 TemplateMatch，MasterMatch 是盲点）
- arena.json 重写成星形：入口 → Router → 流程节点 → 回 Router
- 删除 Arena_MainPage / HomePage / MasterPage / WaitPick / WaitBattle / LeaveSettle /
  Mode_1v1 / Mode_Master；interface 里 arena_master 的 pipeline_override 一并删除
- combat.json 的 Fight_Once.next 清空（它同时是「战斗·单场」的 entry，打完要结束；
  arena 流程里由 Router 的 override_pipeline 改成回 Router）

**为什么路由目标必须是 DirectHit**：override_next 只改候选列表，下一轮仍要重新识别；
目标若是 TemplateMatch，重新截图时画面已变（转场）就识别失败，节点不执行、next 又
没人管 → 整个 task 直接结束，外壳只打一行「任务已全部完成」。

**两个必须分流的坑**：
1. 大师团页：Router 判 team → TeamFix 补人 → 回 Router 还是 team → 死循环，
   永远不点匹配。现在 `_team_step` 按卡位分流：全有卡 → MasterMatch，缺卡 → TeamFix。
2. 点完匹配战斗后页面不变（匹配中），Router 每 300ms 判一次 team 会连点几十下 →
   `match_cooldown_s=20`，点过后 20s 内只等待（Arena_UnknownWait）。

**卡位阈值 0.72（不是 TeamFix 的 0.85）**：现场帧 `debug/_match_click.png` 第 3 个卡位
只有 0.776（角色头像挡了半个 SSR 标签），队伍明明是满的。宁可把「有卡」判成满员
（直接匹配），也不要把满员判成缺人（会进 TeamFix 把已上阵角色点下阵）。

**选人页判据**：只靠 pick_recent/pick_wait 会漏「列表滚动过的选人页」
（现场帧 0.586/0.772）。加 `master_pick_tip`（底部「温馨提示：请选择格斗家」，
ROI [520,645,240,70]，选人页 0.884~0.99 / 其余 0.23~0.38，阈值 0.8）。
这个模板名字有历史误导性，它不是大师专属。

**验证**：
- `debug/_vid3` 40 帧全流程回放（1920×1080 抽帧缩到 1280）：city→home、arena_page→arena、
  vs/加载/一穿三/至尊赛→unknown、pick→pick、battle/battle_end→fight、settle→settle，全对
- 25 个回归脚本全绿（新增 _test_v1230.py 99 项；重写 _test_nav_chain 为星形结构基线；
  _test_anticlick [4][5] 段换成 Router 判据 + 40 帧回放；_test_rankup / _test_v1225 跟着改）
- schema 校验通过

**补一条（同版）**：`ArenaPick` / `MasterPick` 失败改成「前 2 次 return True 交回 Router
重判，连续 3 次才 return False」。原来 return False = 节点失败 = 整个 task 结束，
外壳只打「任务已全部完成」，一次误判就停挂机。

## v1.2.31（未知页 0.5s 自救快通道）

用户问「连续 25 秒才交给安全返回意思是未知页面会挂起 25s 吗？会不会太长了？改成 500ms」。

**先纠正前提**：未知页从来不挂起。Router 每轮都在重新截屏重判，页面一变立刻路由；
25s 只是「连续 25s 一次都认不出才点一次返回」的保险丝。但「真掉进认不出的子页面
要等 25s 才自救」确实太久 —— 所以照样改。

**改法（关键：0.5s 不是无条件返回）**
- `unknown_back_s` 25 → 0.5：未知满 0.5s 进快通道。
- 快通道每轮本地找右上角红色返回箭头，**找到才交 ArenaSafeBack**；找不到继续等。
- `unknown_back_hard_s=25` 留作「连箭头都认不出的怪页面」兜底。
- `unknown_need_arrow=false` 可退回旧的「到点就盲点」。

**为什么不能无条件 0.5s 返回**：VS 入场 2~4s、每局加载 5~7s、一穿三/至尊赛播报全判
unknown。无条件返回 = 这十秒里每半秒盲点一次 (1244,28)，正好原样复现 v1.2.30 刚修掉的
「路上误点其他界面」。

**顺带修掉一个既有隐患（重要）**：`CombatFighter._find_red_back` 的 ROI 是 x>=900 / y<95，
把战斗 HUD 里 y=60~86 的红色元素（血条、技能光圈）、主城图标 (1244,86)、加载页装饰
(1267,85) 全认成返回箭头。新增 `page_router._red_back_xy`（x≥1040 / y<56）：
- 录像 36 帧：真箭头 竞技场主页/至尊赛 (1242~1244,28)、装备页 (1110,33) 全部保留；
- 过渡帧（vs/loading/ko_streak）误命中 **5 → 0**（f0148.8 的 (1267,85) 被切掉）。
- 战斗帧仍会命中 (1220,28)，但战斗一定先被 `_detect` 判成 fight，进不了未知页，无影响。

**其他**：
- `Arena_UnknownWait.post_delay` 600 → 200（一轮 900ms → 500ms），让 0.5s 真的半秒级生效。
- Router 截图改 `_grab_both(ctrl)`：一次 post_screencap 同时返回灰度 + 彩色，不额外 IPC。
- `_unknown_step` 签名 `(ctrl, param)` → `(color, param)`。

**验证**：`_test_v1230.py` 110 项全绿（新增 12 项：0.4s 仍等 / 0.6s 有箭头返回 /
0.6s 无箭头仍等 / 10s 无箭头仍等 / 26s 硬兜底 / need_arrow=false 可回退 /
11 张过渡帧零误命中 / 竞技场主页与至尊赛箭头仍能认出）。25 个回归脚本全绿，schema 通过。

## v1.2.32（按澄清改回：未知页纯等待，5s 兜底，0.25s 轮询）

用户澄清：「加载页之类的未知界面需要**挂起等待**，直到进入可识别页面。误点兜底按你说的
连续 n 秒一次都认不出才点一次返回，n 改为 5，页面挂起修改为 0.25s」。

**复盘 v1.2.31 的理解错误**：他说「改成 500ms」，我理解成「500ms 就开始判断/返回」，
实际他指的是**未知页的挂起轮询间隔**。v1.2.31 做的「0.5s + 必须看到红箭头才点」技术上是
对的（录像验证零误点），但语义方向反了 —— 要的是「等」，不是「提前返回」。

**最终参数**
- `unknown_back_s = 5.0`：连续未知 5s 才点一次返回，之前一次都不点
- `unknown_need_arrow = false`（默认）：v1.2.31 的箭头守卫降级为可选
- `unknown_back_hard_s = 5.0`：仅 need_arrow=true 时生效
- `Arena_UnknownWait.post_delay = 250` + Router `rate_limit 300→200`：**两处都要改**，
  否则 rate_limit 会把 0.25s 轮询兜成 0.3s 以上

**行为**：未知页每 0.25s 重截重判 → 变成 pick/arena/home/fight 等立刻路由；连续 5s 认不出
才点一次 `ArenaSafeBack` → 回 Router 重新数 5s。

**验证**：`_test_v1230.py` 112 项全绿，新增覆盖 0.3/1.5/3.0/4.5s 全程只等不点、
5.1s 才点一次、返回后重新计 5s、need_arrow=true 保守路径仍可用。25 个脚本全绿，schema 通过。

**发版**：commit cc99591，tag v1.2.32。覆盖包 `MaaKOF_Fate_update_v1.2.32.zip`（3 文件），
备份 `debug/_bak_v1232/` 后覆盖安装目录。**GitHub 仍未通**（v1.2.30/31/32 三个 tag 待补推）。
