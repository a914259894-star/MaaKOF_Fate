# 2026-11-06

## v1.2.30 竞技场页面路由重构（单入口 + 依次判页）

**用户诉求**：1v1 用 v1.2.27 时「误点其他界面好多次」。要求改成：
「从一个入口进入 → 所有页面依次判别（战斗最优先、未知界面等待）→ 判出是哪个页面
再进那个页面的流程 → 走完一次流程回到入口 → 再判一次」。

**根因**：旧 arena.json 是「每个节点各写一串 next」，同一批候选复制十几份，而且
next 里混着**点击**节点：
- `Arena_Enter_1v1` 只看 `main_arena_btn`、阈值 0.7 就点
- `Arena_Enter_Master` 三个模板全是 0.7
- `Arena_MasterMatch` 是完全盲点 (1135,634)
只要某个宽泛模板在错误页面误命中，就在那一页点一下。

**改法**：
- 新增 `assets/agent/page_router.py`
  - `ArenaRouter`：截一张图，本地 cv2 按优先级判页
    `战斗 > KOF段位提升 > 胜负结算 > 选人 > 大师团 > 竞技场主页 > 主城 > 未知`
    → `context.override_next(argv.node_name, [目标])` 精确路由
    → 同时 `override_pipeline({目标: {"next": [自己]}})` 把回路改回当前 Router
      （1v1/大师是两个 Router 节点，不改回路会串模式）
  - 竞技场主页点 1V1/大师、主城点 KO竞技，都在 Router 内做，且**先模板命中才点**
  - 未知页只等待，连续 25s 才交 `ArenaSafeBack`
  - `ArenaSettleOk` / `ArenaRankUp` / `ArenaMasterMatch`：DirectHit + 自定义动作，
    动作内部先复核页面再点（原来 SettleOk/RankUp 是 TemplateMatch，MasterMatch 是盲点）
- arena.json 重写成星形：入口 → Router → 流程节点 → 回 Router
- 删除 Arena_MainPage / HomePage / MasterPage / WaitPick / WaitBattle / LeaveSettle /
  Mode_1v1 / Mode_Master；interface 里 arena_master 的 pipeline_override 一并删除
- combat.json 的 Fight_Once.next 清空（它同时是「战斗·单场」的 entry，打完要结束；
  arena 流程里由 Router 的 override_pipeline 改成回 Router）

**为什么路由目标必须是 DirectHit**：override_next 只改候选列表，下一轮仍要重新识别；
目标若是 TemplateMatch，重新截图时画面已变（转场）就识别失败，节点不执行、next 又
没人管 → 整个 task 直接结束，外壳只打一行「任务已全部完成」。

**两个必须分流的坑**：
1. 大师团页：Router 判 team → TeamFix 补人 → 回 Router 还是 team → 死循环，
   永远不点匹配。现在 `_team_step` 按卡位分流：全有卡 → MasterMatch，缺卡 → TeamFix。
2. 点完匹配战斗后页面不变（匹配中），Router 每 300ms 判一次 team 会连点几十下 →
   `match_cooldown_s=20`，点过后 20s 内只等待（Arena_UnknownWait）。

**卡位阈值 0.72（不是 TeamFix 的 0.85）**：现场帧 `debug/_match_click.png` 第 3 个卡位
只有 0.776（角色头像挡了半个 SSR 标签），队伍明明是满的。宁可把「有卡」判成满员
（直接匹配），也不要把满员判成缺人（会进 TeamFix 把已上阵角色点下阵）。

**选人页判据**：只靠 pick_recent/pick_wait 会漏「列表滚动过的选人页」
（现场帧 0.586/0.772）。加 `master_pick_tip`（底部「温馨提示：请选择格斗家」，
ROI [520,645,240,70]，选人页 0.884~0.99 / 其余 0.23~0.38，阈值 0.8）。
这个模板名字有历史误导性，它不是大师专属。
