## v1.2.18：纯性能优化（用户报「占用很高，开的东西多一点就很卡」）

### 先量化（不是猜）
- 现场 `debug/maa.log`：**5 分钟 155MB / 158284 行**，平均每行 981 字节（TRC/DBG 行带完整 JSON），`maa.bak.log` 166MB。`logging: true` + `stdout_level: 2`，`save_draw` 本来就 false。
- `context.run_recognition` 的真实成本（从 maa.log 的 `handle_context_run_recognition | leave, Xms` 统计）：**P50 14ms / P90 46ms / 最大 121ms**（336 次样本）。**不是代码注释里写的 400~800ms**（那是历史值，该注释已过时但未改，避免误导后面的人）。
- 主循环一轮 ≈ 600ms（相邻两次 run_recognition 的 req 时间戳差）：截图 ~60ms + cv2 18ms + 8 次 tap（hold 30ms + gap 30ms）= 480ms + IPC ~20ms。
- cv2 单轮：cvtColor 0.38ms / team(560x90) 0.76ms / **home 全屏(85x85 over 1280x720) 15.27ms ← 占本地部分 84%** / rankup(720x130) 1.85ms。`cv2.getNumThreads()=32`，压到 1 反而更快（15.27→14.25ms）。

### 做了什么
1. `config/maa_option.json` + `assets/config/maa_option.json` + `install/config` → `logging: false`（`save_on_error: true` 保留）。
   **以后排查要先把它改回 true 复现一次**，否则没有 maa.log。
2. `combat_actions.py`：新增 `_load_reco_cfg()`（启动时从 `resource/pipeline/combat.json` 读所有 `SkillReadyBright` 节点的 roi + param）+ `_ready_metric()`（与 `combat_recognition._metric` 逐行等价）+ `CombatFighter._ready_hit()` / `_first_hit()`。主循环的替身判定改成本地 numpy（22µs vs IPC 14ms+），`confirm>1` 或读不到文件时自动回落 IPC。
   **参数不写死是刻意的**：改 combat.json 的 roi/阈值，本地实现自动跟随，不会漂移。
3. `register.py` 顶部 `cv2.setNumThreads(1)`（两个入口都 import register）。
4. `tools/install.py` 新增 `install_config()`：把 `assets/config` 打进 `install/config`（以前是手工放的，容易忘）。
