## 竞技1v1循环「快速选人关闭 + 栏位 picks 不生效」排查（已纠偏）

- 机制：`agent/arena_actions.py` 的 ArenaPick 按 `quick_pick` 分流——`true` 走 `_quick()`（点近期使用最左列，**忽略 picks**），`false` 走 `_roster()`（模板匹配 `picks`）。
- 运行时 `debug/maa.log` 显示 Arena_Pick 收到 `custom_action_param={"quick_pick":true, "picks":[[1,1,1],[1,2,1],[1,3,1]], ...}`：说明「关闭」选项的 `pipeline_override`（quick_pick:false + 用户 picks [[1,1,1],[2,1,1],[3,1,1]]）**从未被应用**，base 原样生效。
- 根因（按 MAAFramework 规范）：`interface.json` 的「快速选人」是 `select` 选项，**未设 `default_case`，默认取第一个 case「开启（推荐）」** → quick_pick:true → picks 被忽略。用户以为选了关闭，但实际选项停在默认的「开启」。
- 第一版我误改了 base 的 `quick_pick:true→false` + picks，**违反 MAAFramework 规范（base 应保留推荐默认值，由 option override 去覆盖）**。已回退。
- 之前曾加 `"default_case": "关闭"` 使关闭成默认，但用户最终决定：**保留「开启」为默认（即移除 default_case，回退到旧版），只把 base 的 `picks` 改为 `[[1,1,1],[2,1,1],[3,1,1]]`**。base 的 `quick_pick` 维持 `true`（不动）。「关闭」case 的 override picks 也保持 `[[1,1,1],[2,1,1],[3,1,1]]`。
- 用户想改栏位：直接编辑 `arena.json` 的 `Arena_Pick.custom_action_param.picks`（或改「关闭」case 的 override），模板图为 `assets/resource/image/arena/roles/c{栏}r{行}k{列}.png`。
