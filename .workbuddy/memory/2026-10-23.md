## v1.2.4：大师场「选人后循环自己停」根因（v1.2.1 现场日志）

用户日志 `D:/Games/MaaKOF_Fate-win-x86_64-v1.2.1/logs/log-20261023.log`（15:08–15:49）+ `debug/on_error/Arena_MasterPick_2026.10.23-15.49.01.636.png`。

### 现场事实
- 15:45:38 MasterPick 开始 → 15:46:00 返回 True（选人 3/3、点确定 score 0.989）→ 之后 `Arena_WaitBattle` 每 ~1s 判一次、连续 3 分钟都不命中（battle_bar 最高 0.507，画面均值恒定=死静止）→ 15:49:01 on_error 截图存证 → 任务结束。
- 那张 15:49 截图是**大师团大厅**（大师竞技场/大师团、匹配战斗、每日大师币 0/6），不是战斗画面。
- 15:46:01 → 15:49:01 正好 **180s**，等于 `Arena_MasterPick.timeout`。所以不是用户手动停，是**节点超时 → task failed → 队列结束**（MFA 外壳仍打「任务已全部完成」，容易误判）。
- 同一份日志里 15:40、15:51 两轮是正常的：MasterPick 结束后 **41s** 才命中 WaitBattle（对手选人/加载），然后开打。

### 根因链
1. `_click_verify` 点完**固定 sleep 0.45s** 就判标记 → 标记还没渲染出来 → 判失败 → **再点一次**。日志里几乎每格都是「第 1 次点击未确认 → 再点」。master 页再点一次等于 toggle，实际选中数变 0，于是输入栏位 3 个命中全判失败 → 走兜底把 13 格各点两遍（15:45:44→15:45:57，14 秒）。
2. 选人阶段被拖到 19s+ 后页面被游戏接管（15:45:57.6 起标记突然全都能立刻确认，紧接着点到的「确定」是别的弹窗上的），点完 2 秒就回到大师团大厅。
3. **`Arena_MasterPick.next` 只有 `Arena_WaitBattle`** —— 回到大厅后没有任何节点能命中，干等 180s 超时，整任务停止。这就是「循环自己停了」。

### 修复
- `_click_verify` 重写：① 点前先看有没有标记（有则免点，避免 toggle）；② 点后**轮询** `mark_timeout=2.0s`（每 `mark_poll=0.12s` 一次截图）等标记出现，只有真等不到才补点；③ 补点前先判页面还在不在。
- 新增 `_left_page` 守卫：`_left_pick_page` 改判据为**「1P」标签在不在**（固定 ROI `[340,320,240,140]`，三帧实测 0.995/0.996 @ (405,363)）。不能用「确定 按钮在不在」——「匹配已取消」弹窗上也有个 确定；也不能全屏找 1P——战斗 HUD 里也有。命中消失 → 阶段立即中断、不点确定、`run()` 返回 True 放行。
- pipeline 兜底：`Arena_MasterPick.next` = [WaitBattle, MasterPage, Mode_Master, Enter_Master, MainPage]；`Arena_Pick.next` = [WaitBattle, MainPage, Mode_1v1, Enter_1v1]（原来都只有 WaitBattle，一旦没进战斗必超时）。
- `interface.json` 的 arena_master 任务 override：`Arena_LeaveSettle.next` 前面加 MasterPage（回到大厅直接点「匹配战斗」，不再先去点标题横幅）、末尾加 MainPage；并补 `Arena_MainPage.next` = [WaitBattle, Mode_Master, Enter_Master]，避免大师任务在大厅页被 base 的 Mode_1v1 抢先去打 1v1。
- 新增 `debug/_test_master_guard.py`：延迟 0.6s 出标记 → 3 格只点 3 次（原来 6 次）；页面消失 → 2.1s 内中断、0 次确定点击、run() 返回 True。version → 1.2.4。
